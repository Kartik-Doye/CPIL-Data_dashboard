1. Executive Purpose & System Architecture

The CPIL GO Gas Executive Intelligence & Analytical Dashboard is an end-to-end operational telemetry, financial audit, replenishment logistics, and self-correcting AI/ML demand forecasting platform built for Confidence Petroleum India Ltd. (CPIL) Auto LPG Dispensing Stations (ALDS).

    A["Manual Work/sale.xlsx\n& TM List.xlsx"] -->|"load_sales.ts / File Watcher"| B[("PostgreSQL Database\nsale_tracker • settings\nforecast_feedback")]

    C -->|"Full-History Series +\n10d Feedback"| D["Adaptive AI/ML Engine\n(forecasting.ts & forecastFixes.ts)"]
    C -->|"7.5 / 10 / 20 KL Fleet\n& Ullage Engine"| E["Tanker Dispatch Engine\n(tanker.ts)"]

    D --> G["Automated Morning Email\n(HTML + 4-Sheet .xlsx)"]
    E --> H["WhatsApp Web Automation\n(Executive Brief + Tanker Manifest)"]

Why This Architecture Was Chosen

1. Single Source of Truth (PostgreSQL sale_tracker): Every report, chart, WhatsApp briefing, and Excel attachment reads from the same normalized 27-column PostgreSQL table (sale_tracker), eliminating spreadsheet copy-paste errors.
2. Zero Hardcoding (product-config.json + PostgreSQL settings): All operational thresholds (critical stock days, tanker fleet capacities, anomaly rules, state code mappings, and station targets) are externalized so business rules can evolve without code changes.
3. Real-Time File Watcher & Cache Invalidation: A file watcher monitors Manual Work/sale.xlsx and triggers /api/telemetry/invalidate as soon as new daily sales are loaded.

2.2 AI/ML Forecasting & Statistical Terms

Term / WordMathematical DefinitionWhy It Is Used in This Product
Walk-Forward Validation (Backtesting)Scoring day $t$ using models trained strictly on days $1 \dots t-1$Prevents "data leakage" (cheating by peeking at future dates). Every accuracy metric in the app is computed via strict walk-forward validation across all historical days in PostgreSQL after the 7-day lag warm-up.
MAPE (%)$\frac{100}{N}\sum_{t=1}^{N} \left\frac{\hat{y}_t - y_t}{y_t}\right$ (for $y_t > 0$)Mean Absolute Percentage Error. Measures average percentage miss per day. Historical Validation Accuracy is defined as $\max(0, 100 - \text{MAPE})$. Zero-sale days ($y_t = 0$) are excluded so division-by-zero never fabricates $100\%$ accuracy.
WAPE (%)$\frac{100 \sum_{t=1}^{N}\hat{y}_t - y_t}{\sum_{t=1}^{N} y_t}$Weighted Absolute Percentage Error. Weights errors by total volume sold so high-volume days carry proportional importance.
RMSE (L)$\sqrt{\frac{1}{N}\sum_{t=1}^{N} (\hat{y}_t - y_t)^2}$Root Mean Squared Error. Penalizes large outlier misses heavily; expressed in Litres (L).
Signed Bias (% or L/d)$\frac{1}{N}\sum_{t=1}^{N} (\hat{y}_t - y_t)$Positive (+) means the model over-predicted ($\text{Predicted} > \text{Actual}$); Negative (-) means the model under-predicted ($\text{Predicted} < \text{Actual}$).
EWMA$E_t = \alpha \cdot x_t + (1 - \alpha) \cdot E_{t-1}$Exponentially Weighted Moving Average. Gives higher weight to the most recent days while smoothing random noise. Used both as a model feature ($\alpha = 0.25$) and in 10-day adaptive residual learning ($\alpha = 0.32$).
P10 / P50 / P90 Quantiles$P_{50} = \hat{y}$, $P_{10} = \hat{y} - 1.28\sigma_h$, $P_{90} = \hat{y} + 1.28\sigma_h$Probabilistic Forecast Fan: $P_{50}$ is the central expected demand; $P_{10}$ is the conservative lower bound ($90\%$ chance actuals exceed this); $P_{90}$ is the upper surge bound ($90\%$ chance actuals stay below this).
Gini Coefficient (0 to 1)$\frac{\sum_{i=1}^n (2i - n - 1) x_{(i)}}{n \sum_{i=1}^n x_{(i)}}$Measures volume inequality across stations (0 = every station sells the exact same amount; 1 = one station sells $100\%$ of network volume).
Lorenz Curve & Pareto 80/20Cumulative % of Stations vs Cumulative % of VolumeIdentifies whether the network is overly dependent on a small handful of flagship stations.
Sample Skewness ($g_1$)$\frac{n}{(n-1)(n-2)} \sum \left(\frac{x_i - \bar{x}}{s}\right)^3$Measures asymmetry of station sales distribution (positive skew = long tail of high-volume flagship stations).
Excess Kurtosis ($g_2$)Unbiased 4th standardized moment minus $3$Measures "tailedness" / outlier concentration compared to a normal bell curve.
Pearson Correlation ($r$)$\frac{\sum (x_i - \bar{x})(y_i - \bar{y})}{\sqrt{\sum (x_i - \bar{x})^2 \sum (y_i - \bar{y})^2}}$Ranges from $-1.0$ to $+1.0$; quantifies linear dependency between any two metrics (e.g., Sale Qty vs Collection, Effective RSP vs Volume).

4. Deep Dive: AI/ML 7-Day Demand Forecast (AIMLForecast.tsx & forecasting.ts)

4.1 Why Predictions Previously Drifted & How Full-Database Adaptive Learning Solves It

1. 100% Database History Training: The SQL loader queries all historical dates present in PostgreSQL sale_tracker (no 28-day or 90-day cutoff). Walk-forward validation scores every single historical day from day 8 (firstTestIndex = 7) through the latest date in the database.
2. 5 Sub-Models in the Ensemble:
• Model 1: Leak-Free Multivariate Ridge Linear Regression (LinearRegressionModel)
• Uses 16 strictly-prior features built by buildFeaturesNoLeak in forecastFixes.ts:
1. dow: Day of week ($0 = \text{Sun} \dots 6 = \text{Sat}$)
2. isWeekend: $1$ if Saturday or Sunday, else $0$
3. dom: Day of month ($1 \dots 31$)
4. isFest: $1$ if date matches an exact festival in festivalCalendar.ts, else $0$
5. lag1: Seasonally-adjusted prior-day volume $\text{rawLag}_1 \times \frac{\text{dowRatio}(d_t)}{\text{dowRatio}(d_{t-1})}$
6. lag7: Exact calendar 7-day prior volume ($t - 7\text{ days}$)
7. r7: Strictly-prior 7-day rolling mean
8. r30: Strictly-prior 30-day rolling mean
9. ewma7: Strictly-prior Exponentially Weighted Moving Average ($\alpha = 0.25$)
10. lag2: Exact calendar 2-day prior volume ($t - 2\text{ days}$)
11. trendAccel: Recent 3-day slope minus prior 3-day slope
12. dowSin: $\sin(2\pi \cdot \text{dow} / 7)$ cyclical weekday wave
13. dowCos: $\cos(2\pi \cdot \text{dow} / 7)$ cyclical weekday wave
14. isSaturday: Explicit Saturday indicator ($1$ if $\text{dow}=6$, else $0$)
15. isSunday: Explicit Sunday indicator ($1$ if $\text{dow}=0$, else $0$)
16. dowExpectedVolume: $r_7 \times \text{dowRatio}(d_t)$, scaling current 7-day volume by the empirical weekday/weekend ratio
• Standardized via z-score and solved via L2-regularized Normal Equations:

$$\hat{\beta} = (X^T X + \lambda I)^{-1} X^T y, \quad \lambda = 1.0$$

• Model 2: Holt-Winters Triple Exponential Smoothing (holtWinters)
• Tracks Level ($\ell_t$), damped Trend ($b_t$ with damping $\phi = 0.92$), and Calendar-Weekday Seasonality ($s_{\text{dow}(t)}$) indexed by date.getDay() so missing dates never shift the weekly cycle:

$$\ell_t = \alpha (y_t - s_{d(t)}) + (1 - \alpha)(\ell_{t-1} + b_{t-1})$$

$$b_t = \beta (\ell_t - \ell_{t-1}) + (1 - \beta) b_{t-1}$$

$$s_{d(t)} = \gamma (y_t - \ell_t) + (1 - \gamma) s_{d(t)}$$

• Grid-searches $(\alpha, \beta, \gamma)$ on a holdout window to minimize MAPE.
• Model 3: Same-Day Last Week (naiveLastWeek)
• Looks up the exact calendar date $t - 7\text{ days}$ (targetTime = forecastDate - 7 * 86400000).
• Model 4: Recency-Weighted Same-Weekday Average (sameWeekdayAvg)
• Computes an exponentially recency-weighted average ($\text{decay} = 0.72^{\text{weeksAgo}}$) across all historical occurrences of that exact weekday in PostgreSQL:

$$\hat{y}_{\text{weekday}}(d) = \frac{\sum_{k=0}^{K-1} y_{d,k} \cdot 0.72^{K - 1 - k}}{\sum_{k=0}^{K-1} 0.72^{K - 1 - k}}$$

• Model 5: Gradient Boosting Regression Trees (GradientBoostingModel)
• Fits 30 sequential decision trees (depth $2$, learning rate $0.05$) on residuals. Automatically promoted into the active ensemble ($20\%$ blend) only when walk-forward validation proves $\ge 5\%$ MAPE improvement and $\ge 60\%$ daily win rate across at least 14 scored days.

4.2 Why Saturday & Sunday Sales Go Down & How the Engine Models It

In commercial Auto LPG operations, commercial fleet/auto-rickshaw refueling drops on Saturday and Sunday compared to Monday–Friday.

• Problem with Naive Linear Models: On Saturday, lag1 is Friday (a high-volume weekday) and r7 contains 5 weekdays. Without adjustment, Friday's high sales pull Saturday's prediction artificially high. Also, if Mon–Fri had strong demand (negative bias), a generic EWMA bias corrector would push Saturday upward.
• 3-Part Weekend Contraction Solution:
1. Empirical Weekday Ratio (computeEmpiricalWeekdayRatio): For every day $k$ in history, computes $r_k = y_k / \text{LocalMean}_7(k)$ with recency decay $0.95^{\text{daysAgo}}$ and compares Saturday ($\text{dow}=6$) and Sunday ($\text{dow}=0$) against the Mon–Fri average:

$$\text{dowRatio}(d) = \frac{\text{WeightedMeanRatio}(d)}{\text{WeightedMeanRatio}(\text{Mon–Fri})}$$

2. Weekend Contraction Calibration (calibrateWeekendPrediction): When predicting a Saturday or Sunday and historical data confirms a weekend drop ($\text{dowRatio} < 0.99$), the engine computes the empirical weekend target $\text{RecentWeekdayMean}_{10} \times \text{dowRatio}$ blended with same_weekday_avg ($30\%$) and naive_last_week ($15\%$), pulling any inflated ensemble estimate down to the true weekend demand regime.
3. Weekend-Isolated Adaptive Bias Memory: In computeAdaptiveBiasPercentage, when dow is Saturday or Sunday, the adaptive corrector weights past Saturday/Sunday residual errors at 75% and general EWMA at 25%, preventing Mon–Fri demand surges from inflating weekend forecasts.

5.3 Tanker Dispatch & Replenishment Engine (TankerDispatchReport.tsx & tanker.ts)

• How Calculations Work:
1. Effective Daily Burn Rate: $\text{Burn}_i = \max(\text{sale\_qty}_i, \text{rolling\_7d\_burn}_i)$ so a station with 0 L sales today but a 1,200 L/d 7-day burn rate is still flagged if its tank is low.
2. Days of Stock Cover: $\text{DaysLeft}_i = \text{closing\_dip}_i \div \text{Burn}_i$.
• Priority 1 (CRITICAL): $\text{DaysLeft}_i < 1.5\text{ days}$ (Immediate Same-Day Dispatch).
• Priority 2 (WARNING): $1.5 \le \text{DaysLeft}_i < 3.0\text{ days}$ (Next-Day Scheduled Dispatch).
• Healthy (ADEQUATE): $\text{DaysLeft}_i \ge 3.0\text{ days}$.
3. Ullage-Capped Refill Volume:

$$\text{RawNeed}_i = \max(0, 3.0 \times \text{Burn}_i - \text{closing\_dip}_i)$$

$$\text{Ullage}_i = \max(0, \text{tank\_cap}_i - \text{closing\_dip}_i)$$

$$\text{RecommendedRefill}_i = \min(\text{RawNeed}_i, \text{Ullage}_i)$$

4. Fleet Allocation (7.5 KL / 10 KL / 20 KL): Selects the smallest single tanker (7,500 L, 10,000 L, or 20,000 L) that satisfies $\text{RecommendedRefill}_i$, or multiple 20 KL tankers if demand exceeds 20,000 L.
